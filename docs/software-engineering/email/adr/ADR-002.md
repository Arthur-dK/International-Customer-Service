# ADR 002: Reject unauthenticated inbound email posts

## Context
SendGrid Inbound Parse has no `X-Twilio-Signature`. The destination URL can carry an HTTP basic-auth user and password, and SendGrid repeats that pair in the `Authorization` header. Phase 2 acknowledges the post. It does not send mail. A public URL without a check would still accept anyone's form.

## Decision
- `POST /email/incoming` requires HTTP basic auth that matches `SENDGRID_INBOUND_USER` and `SENDGRID_INBOUND_PASSWORD`.
- An empty configured user or password, a missing header, or a mismatch returns HTTP 403 and sends no mail.
- A match returns HTTP 200 with an empty body. The parsed plain text is kept off the log. The log records the envelope sender, the envelope recipient, whether the plain text is non-empty, and whether auth passed.
- File uploads are not read into the field map.

## Trade-off Analysis
- **Benefit:** A forged POST cannot pass once the password stays in `.env` and in the SendGrid URL. The same 200 is what later phases return after a successful send.
- **Drawback:** The password has to match in both places. A SendGrid URL without the user and password receives 403 for every real message.
