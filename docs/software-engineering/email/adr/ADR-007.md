# ADR 007: Email-owned English placeholders

## Context
The goal is to get the program to name one of five card actions from an email, or name nothing. The reply text for those cases is still the FEAT-01 echo. The IVR already has spoken lines for the same actions, and SMS already has its own English lines, including a different sentence when nothing matches. Email needs its own copies so a later change to one channel does not change the others. Nothing is stored between emails, so block and unblock cannot ask a later yes or no.

## Decision
- The reply strings live in `services/email/replies.py`. They are not read from `core/language/phrases.json` and they are not imported from SMS or from the IVR.
- Every reply is English:
  - Balance: "I confirm you wish to check the balance. This is a placeholder."
  - PIN: "I confirm you wish to check the PIN. This is a placeholder."
  - Statement: "I confirm you wish to check the statement. This is a placeholder."
  - Block: "I confirm you wish to block the card. This is a placeholder."
  - Unblock: "I confirm you wish to unblock the card. This is a placeholder."
  - No match, including two actions: "I didn't understand what you meant by that."
- The PIN line has no digits and no real PIN. None of the lines report a real balance or card status.
- `reply_for` returns the line for one action id from [ADR-006](ADR-006.md). An unknown action id is an error. Nothing returns the no-match sentence.
- This module does not send email. The webhook still echoes the plain text until Phase 3. Empty text, a bad password, the daily cap, and Message-ID dedupe stay as they are.

## Trade-off Analysis
- **Benefit:** The five lines and the no-match sentence can change for email alone, and the spoken IVR catalog stays untouched.
- **Drawback:** A sender who writes in another language will still receive English once these lines are sent. There is no second email to confirm a block or an unblock.
