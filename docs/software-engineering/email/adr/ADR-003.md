# ADR 003: Echo the plain text through Mail Send

## Context
A password-checked inbound post is acknowledged and then dropped. The reply has to be the same plain-text characters, sent from the address that received the mail. SendGrid will not add that reply on its own. The trial allows about 100 sent emails a day, and an open address can be spammed.

## Decision
- A non-empty `text` field is sent with `POST https://api.sendgrid.com/v3/mail/send`. The body of that call is the inbound plain text, unchanged.
- The Mail Send `from` is the envelope recipient. The Mail Send `to` is the envelope sender. The subject is `Re:` plus the inbound subject.
- HTML is not sent. An empty or blank `text`, or a missing sender or recipient, returns HTTP 200 and does not call Mail Send.
- The call runs in a worker thread. A failed call returns HTTP 500 so SendGrid can retry. The body and the subject are not logged.
- `EMAIL_DAILY_SEND_CAP` defaults to 20 for the UTC day, in this process. At the cap the webhook still returns 200 and does not send. A failed send gives that reservation back.

## Trade-off Analysis
- **Benefit:** The reply can be the exact inbound text, and a burst cannot use the whole trial day.
- **Drawback:** The app must hold `SENDGRID_API_KEY`. The cap resets when the process restarts, and a SendGrid retry of a successful send can echo a second time until dedupe exists.
