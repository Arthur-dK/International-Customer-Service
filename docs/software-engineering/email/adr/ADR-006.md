# ADR 006: English whole-word email intents, two actions are no match

## Context
FEAT-01 echoes the text of 1 email. This placeholder is not an intent model. The same five card actions used for IVR and SMS are needed here: balance, PIN, statement, block, and unblock. The IVR already maps those actions from keywords ('balance', 'block', etc.), and two actions in one utterance are no match. SMS uses the English words only, and returns the earlier action when two appear. Other languages will be added for email in a later feature.

## Decision
- Add `match_intent` in `services/email/intent.py`. It returns one of `get_balance`, `get_pin`, `get_card_statement`, `block_card`, `unblock_card`, or nothing.
- Only the English words are used: balance, pin, statement, block, unblock. The French, Hebrew, Arabic, and Swahili lists in the IVR router are not copied here.
- The intent ids and the keyword table live in the email module. They are not imported from SMS or from the IVR.
- Normalize by casefold, stripping punctuation, and stripping combining marks, then split on words. A keyword hits only as a whole token. "Unblock" is not "block".
- When two different actions appear, return nothing. The same action repeated still matches that action.
- Empty text, punctuation only, and a sentence with none of the five words return nothing.
- This function does not send email and does not store the text. The webhook still echoes until a later phase of this feature.

## Trade-off Analysis
- **Benefit:** The five actions can be tested from a string, with the same whole-word rule as the English IVR, and a mixed email is not answered as one of the two actions. SMS and the call router stay unchanged.
- **Drawback:** A sentence that avoids the English keyword does not match. A word such as "blocking" does not match "block". A later language feature has to add its own keyword table inside the email module.
