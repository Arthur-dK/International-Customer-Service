# ADR 005: Remember Message-ID in memory

## Context
SendGrid retries the inbound webhook when the HTTP response is slow or a 5xx. A second delivery of the same mail would send the echo again. Some posts arrive without a Message-ID.

## Decision
- After a send is accepted, the process remembers that message. A later POST with the same key returns 200 and does not send again.
- The key is the Message-ID from the raw headers. When that header is missing, the key is a hash of the sender, the recipient, and the plain text.
- The set lives only in this process. It is not written to disk.
- If the Mail Send call fails, that key is not kept and the webhook returns HTTP 500 so SendGrid can retry.
- A restart clears the set. A retry after a restart can send a duplicate.
- An empty body does not send and is not remembered. A bad password is not remembered.

## Trade-off Analysis
- **Benefit:** A normal SendGrid retry does not spend a second echo.
- **Drawback:** Two app processes, or a retry after a restart, can still send twice. The same text from the same person, with no Message-ID, is treated as one message.
