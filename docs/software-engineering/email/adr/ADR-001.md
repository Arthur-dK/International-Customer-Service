# ADR 001: Receive mail through SendGrid Inbound Parse

## Context
Twilio does not issue an email address the way it issues a phone number. Inbound mail has to land on a domain this project controls, and SendGrid has to POST each message to the app. The account should stay as cheap as the product allows. A live reply is a later phase. This record only chooses the account, the hostname, and the webhook URL.

## Decision
- Use a Twilio SendGrid Email API trial. The trial is $0 for 60 days and allows about 100 sent emails per day. Leave the payment method blank, and leave Marketing Campaigns unused. When the 60 days end, sending stops unless the account is upgraded.
- Buy one domain whose DNS host shows MX and CNAME records. The mailbox hostname is `inbox.<that-domain>`. Its MX record is priority 10, target `mx.sendgrid.net`. The apex MX stays untouched.
- Authenticate the root domain in SendGrid with automated security left on and link branding left off. That authentication is separate from the `inbox` MX record. Authenticating `inbox.<that-domain>` itself, with automated security on, would put a CNAME and an MX on the same name and can bounce mail in a loop.
- Inbound Parse receiving domain is `inbox.<that-domain>`. Destination URL is `https://<user>:<password>@<public-host>/email/incoming` on the same HTTPS tunnel used for SMS. Leave “POST the raw, full MIME message” off, so the post includes a parsed `text` field. Leave the spam check off.
- The address to email is `echo@inbox.<that-domain>`. Any other local part is fine except `abuse`, `postmaster`, and `unsubscribe`.
- Store `SENDGRID_API_KEY`, `SENDGRID_INBOUND_USER`, and `SENDGRID_INBOUND_PASSWORD` in `.env`. The API key is restricted to Mail Send. The app does not read these values in this phase.

## Trade-off Analysis
- **Benefit:** One domain registration is the only required spend. The trial needs no card, and a dedicated `inbox` hostname leaves ordinary mail on the domain alone.
- **Drawback:** The trial ends after 60 days. A reply From `echo@inbox.<that-domain>` may need that hostname authenticated later, with automated security off, because a subdomain does not inherit the root domain’s authentication.
