# ADR 025: Task dialogue stays on the existing media stream

## Context
Language selection already owns `WebSocket /media-stream`. Phases 2–4 can route an action, play a canned line, ask for yes or no, and open a keypad. Those steps were proven on the turn engine. They still had to be the same call the caller is already on.

## Decision
- After language selection, the task menu, replies, confirm step, and keypad run on that same media stream. There is no second socket.
- No new speech engine is added for this phase. Tests use the scripted recognizer, which ignores audio and returns a queued transcript. The live process keeps the recognizer already configured.
- A keypad digit after language selection is a task key or a confirm key. It is not another language choice.

## Trade-off Analysis
- **Benefit:** A fake Twilio stream can show the whole dialogue, and a phone call uses the path the caller already hears.
- **Drawback:** The test recognizer does not hear the tone it is sent. It returns the transcript the test queued. Hearing real speech stays with the live recognizer.
