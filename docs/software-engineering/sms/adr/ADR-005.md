# ADR 005: English whole-word SMS intents, earliest action wins

## Context
The IVR already maps five card actions from whole-word keywords after the caller has chosen a language. SMS has no language-selection step, and this placeholder is not an intent model. The same five actions are needed from one text: balance, PIN, statement, block, and unblock. On a call, two actions in one sentence are no match. For this placeholder, a choice between two actions does not matter.

## Decision
- Add `match_intent` in `services/sms/intent.py`. It returns one of `get_balance`, `get_pin`, `get_card_statement`, `block_card`, `unblock_card`, or nothing.
- Only the English words are used: balance, pin, statement, block, unblock. French, Hebrew, Arabic, and Swahili keyword lists are not copied here.
- Normalize by casefold, stripping punctuation, and stripping combining marks, then split on words. A keyword hits only as a whole token. "Unblock" is not "block".
- When two different actions appear, return the one whose token starts earlier in the text. The IVR rule, which returns nothing for two actions, stays on the call path.
- Empty text, punctuation only, and a sentence with none of the five words return nothing.
- This function does not send an SMS and does not store the text.

## Trade-off Analysis
- **Benefit:** The five actions can be tested from a string, with the same whole-word rule as the English IVR, and the call router is left alone.
- **Drawback:** A sentence that avoids the English keyword does not match. A word such as "blocking" does not match "block".
