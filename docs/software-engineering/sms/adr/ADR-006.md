# ADR 006: Detect the text language, reply in English

## Context
A call picks a language before the intent router runs. An SMS does not. The language of the one inbound text has to be known before the reply is written. Detection must be free, offline, low overhead, and finish in under 4 seconds, and it must cover many languages. The IVR phrase catalog only has lines for five languages, and those lines are not reused for SMS. Every SMS reply in this placeholder is English.

## Decision
- Detect the language with `py3langid`. The model is bundled, covers about 97 languages, does not call the network, and installs on Windows without a compiler.
- Run detection on the inbound body before choosing the reply. A blank body or a detector failure is recorded as `en`.
- The detected code does not choose keywords and does not choose the reply language. English keywords still run on the raw text, so "pin" can match when the detector names another language.
- Log the language code. Do not log `Body`.
- Official fastText covers more languages. It needs a native build and a separate model file, so it is not used here.

## Trade-off Analysis
- **Benefit:** Language id is in place for a later reply language, without a paid API and without waiting on the five IVR languages.
- **Drawback:** About 97 languages is short of the fastText set. A one-word text is a weak sample, and the English reply ignores the code this placeholder detects.
