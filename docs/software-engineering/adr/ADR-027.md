# ADR 027: Echo SMS through the Messages API

## Context
An inbound text to the existing Twilio number should come back as the same characters. Twilio can send that reply as TwiML `<Message>` on the webhook response, or the app can send it with the Messages REST API. The voice webhook already returns TwiML for calls. SMS on this number is a separate webhook.

## Decision
- The reply is `messages.create` on the official Twilio Python package, not a TwiML `<Message>`.
- A valid webhook still answers with an empty `<Response/>`, so Twilio does not send a second text of its own.
- The outbound `From` is the inbound `To` (this Twilio number). The outbound `To` is the inbound `From`.
- The client call runs in a worker thread so the FastAPI loop is not blocked.
- Phase 2 sends only when the sender is on the voice allowlist and `Body` is non-empty. Any other signed text still gets the empty document and no SMS. A failed Messages API call returns HTTP 500. The body is not written to the log.

## Trade-off Analysis
- **Benefit:** The same client can send a reply that is not a copy of the webhook body, which a TwiML `<Message>` cannot do as cleanly once the text is chosen in code.
- **Drawback:** The app must hold the auth token and place a second request. A number that is not on the allowlist still gets no reply until Phase 3.
