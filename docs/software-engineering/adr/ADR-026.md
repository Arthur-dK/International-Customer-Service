# ADR 026: Caller audio stays in memory

## Context
The call hears a placeholder PIN line and logs the caller's number and the transcript. Caller audio has to be checked so it is not left on disk, and a PIN must not be written into the logs as digits.

## Decision
- Caller audio stays in memory for the length of the utterance. A finished turn does not add a `.wav` or `.mp3` under the repo.
- Windows speech and Piper may write a temporary `.wav` while they synthesize or recognize. That directory is deleted before the call continues. Static `.cache` prompt audio may stay.
- Logs may include the full calling number on `incoming_call`, and they may include the transcript. They must not include a PIN as digits or as spelled-out numbers, such as `1234` or "one two three four".

## Trade-off Analysis
- **Benefit:** A test can fail the build when a turn starts saving caller audio or logging a PIN.
- **Drawback:** The calling number remains in the call log. The transcript remains too, so a spoken PIN that the recognizer wrote down would still be in that log.
