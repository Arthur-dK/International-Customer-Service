# ADR 029: Reject unsigned SMS webhook posts

## Context
The voice webhook does not check `X-Twilio-Signature`. The SMS webhook will spend credit once it sends a text. Anyone who can reach the public URL could otherwise trigger that send. Phase 1 of FEAT-05 adds the check before any send exists.

## Decision
- `POST /sms/incoming` requires a valid `X-Twilio-Signature` over the public URL and the form fields, using `TWILIO_AUTH_TOKEN` and the official Twilio request validator.
- The signed URL is the URL Twilio called: the `Host` header, `X-Forwarded-Proto` when it is `http` or `https`, and `https` when the host contains `ngrok`. The query string is part of that URL.
- A missing or invalid signature returns HTTP 403 and sends no SMS.
- A valid signature returns HTTP 200 and an empty `<Response/>`. Phase 1 does not read the allowlist and does not call the Messages API.

## Trade-off Analysis
- **Benefit:** A forged POST cannot pass the check once the auth token stays secret. The same empty document is what later phases return so Twilio does not add its own reply.
- **Drawback:** The token in `.env` must be the live auth token, and the reconstructed URL must match the URL Twilio signed. A wrong `Host` or scheme rejects a real text.
