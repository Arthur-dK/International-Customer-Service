# ADR 030: Remember MessageSid in memory

## Context
Twilio retries the SMS webhook when the HTTP response is slow or a 5xx. A second delivery of the same inbound text would send the echo or the rejection again.

## Decision
- After a send is accepted, the process remembers that `MessageSid`. A later POST with the same sid returns empty `<Response/>` and does not send again.
- The set lives only in this process. It is not written to disk.
- If the Messages API call fails, that sid is forgotten and the webhook returns HTTP 500 so Twilio can retry.
- A restart clears the set. A retry after a restart can send a duplicate.
- An empty body does not send and is not remembered. A bad signature is not remembered.

## Trade-off Analysis
- **Benefit:** A normal Twilio retry does not bill a second SMS.
- **Drawback:** Two app processes, or a retry after a restart, can still send twice. The sid list is lost when the process exits.
