# ADR 022: Hear language selection in this phase; add languages without a rewrite

## Context
Language selection was turned off so a call went straight to the English task menu. That call could not be heard the way a caller will hear it. The phrase catalog and intent keywords for French, Hebrew, Arabic, and Swahili are already written. Those languages will be turned on in a later feature branch.

## Decision
- Language selection stays on the live call. The caller hears the language prompt, then the task menu.
- This phase speaks and transcribes English on this PC. When the selected language has no matching voice, the existing rule applies: play the English line, not an English voice reading the other language.
- French, Hebrew, Arabic, and Swahili text and intent keywords stay in the repo. They are not deleted.
- Adding a language later does not replace the call flow. Add that language's catalog lines, its keywords in `route_intent`, a voice whose `supports_language` matches, and speech-to-text that accepts that language code. The media stream, language selector, turn engine, and router stay as they are.

## Trade-off Analysis
- **Benefit:** This phase can be called and heard end to end before it is committed, and the next language is data on the same path.
- **Drawback:** Until a voice and a recognizer exist for a language, choosing it still plays the English fallback for lines that have no voice.
