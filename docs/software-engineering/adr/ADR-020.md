# ADR 020: Allowlist gate before language selection

## Context
Card actions must not start until the calling number is known. The only security check is that number. Language selection today begins as soon as the Voice webhook opens a media stream, including for missing or unknown callers.

## Decision
- The allowlist is `core/telephony/allowed_callers.json`, a `numbers` array of E.164 strings. The webhook reads that file only. There is no environment override. The committed file starts empty, so every call is rejected until a number is added. A number placed in the file is committed with the repo.
- Match is exact after trimming surrounding spaces. Internal spaces do not match. Missing, blank, and non-numeric values such as `anonymous` are not allowed.
- An allowed number still receives TwiML that opens the media stream, with the same `from` and `country_code` parameters as before.
- Any other number never opens the stream and never starts language selection. Twilio fetches the first webhook while the call is still ringing, and `<Hangup>` in that document does not end the call. The webhook returns `<Say>`, waits one second, then `<Redirect>` to `/voice/hangup`, whose only verb is `<Hangup>`.
- The spoken line uses the phone's country prompt language from the existing country table when Twilio `<Say>` can speak it: English `en-US`, French `fr-FR`, Hebrew `he-IL`, Arabic `ar-XA`. Swahili and every other prompt language use the English line, because Twilio `<Say>` has no Swahili voice. An unknown country also uses English.

## Trade-off Analysis
- **Benefit:** Unrecognised callers never reach language selection or the task menu, and no call audio is streamed for them.
- **Drawback:** The allowlist is a committed JSON file, so a real number added there is in git. Kenyan numbers hear the English rejection until a later speech path can speak Swahili.
