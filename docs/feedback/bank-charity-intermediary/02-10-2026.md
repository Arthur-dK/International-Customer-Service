## Points

### F1 — Open on a keypad choice, not a spoken language list

He suggested the call should not read the languages out. It should start with a short keypad line: press 1 for English, press 2 for another language.

**Disposition:** Declined. That opening is an extra step before the caller reaches a language.

### F2 — Feature notes should be scoped, and testable

Two changes to the user-experience sections in the feature notes:

- A feature note should describe only what that feature adds. A note does not need to open with “the user calls the number” when placing the call is not part of that feature.
- Each note should include a short list he can try himself. Every line on the list is expected to work. Anything left off the list is not part of what that feature claims.

**Disposition:** Accepted.

**Resolution:** The user-experience section of each feature note now says only what that feature adds, then a list to try on a call. Each line on the list is expected to work. Anything left off is not part of that feature. He recommended trying languages the builder cannot speak. That testing had not been started.

**Disposition:** In progress. I am working on this.
